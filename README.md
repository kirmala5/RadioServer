# RadioServer — сервер интернет-радио на ASP.NET Core

Учебный проект по лабораторной работе: HTTP-потоковая передача аудио,
несколько радиопоточных станций, веб-плеер на HTML5 `<audio>` и учёт
слушателей в реальном времени.

> **Отклонение от ТЗ:** в среде установлен только .NET SDK 10.0, поэтому
> проект нацелен на `net10.0`. Перенос на .NET 6/7/8 — замена одной строки
> `<TargetFramework>net10.0</TargetFramework>` в `RadioServer.csproj`.

---

## Что реализовано

| Требование | Реализация |
|------------|------------|
| ASP.NET Core веб-приложение | Minimal API (`Program.cs`), .NET 10 |
| Эндпоинт `/stream/{станция}` | `Content-Type: audio/mpeg`, `Transfer-Encoding: chunked`, без `Content-Length` |
| Несколько станций | `/stream/rock`, `/stream/jazz`, `/stream/pop`, `/stream/classic` |
| Веб-плеер `<audio>` | `wwwroot/index.html` + `player.js` + `style.css` — интерфейс в стиле SoundCloud |
| Переключение станций | выпадающий список + карточки станций в плеере |
| Несколько одновременных клиентов | каждый клиент получает свой `FileStream` |
| Счётчик слушателей | `/stations` возвращает `listeners` на станцию |
| Корректное отключение | `HttpContext.RequestAborted` → `RemoveListener`, освобождение ресурсов |
| Ошибки | отсутствующая станция → 404, битый трек → пропуск, разрыв соединения → `IOException` |

### Интерфейс (тема plaza.one)

Веб-плеер оформлен в стиле https://plaza.one/:

- тёмная эстетика (`#0a0a0a`) с неоновыми акцентами (`#00d4ff` cyan, `#ff006e` розовый, `#8338ec` фиолетовый);
- фоновое неоновое свечение и стеклоэффекты (`backdrop-filter: blur`, полупрозрачные панели);
- большая круглая кнопка Play / Пауза с неоновым свечением;
- цветные обложки станций с градиентами, подбираемыми по названию станции;
- волнообразный визуализатор воспроизведения;
- карточки станций с обложкой, названием, числом слушателей и кнопкой «Играть»;
- прогресс-бар и отслеживание времени воспроизведения;
- обновление статуса станций (трек, слушатели) каждые 5 секунд через `fetch('/stations')`.

бинарники не хранятся в репозитории — достаточно запустить сервер.

## Как запустить

Нужен .NET SDK 6/7/8 или 10.

```bash
# 1. Перейти в папку проекта
cd RadioServer

# 2. Восстановить пакеты и собрать
dotnet build -c Release

# 3. Запустить
dotnet run -c Release
```

По умолчанию сервер слушает `http://127.0.0.1:5033` (launchSettings.json).
Открыть в браузере:

| Адрес | Что открывается |
|-------|-----------------|
| http://127.0.0.1:5033/ | веб-плеер (редирект на /index.html) |
| http://127.0.0.1:5033/stations | JSON со станциями и числом слушателей |
| http://127.0.0.1:5033/stream/rock | аудиопоток станции «рок» |

## Как это работает

### Потоковая передача (`/stream/{station}`)

Сервер не отдаёт файл целиком. Он читает MP3-файл блоками по 8 КБ и пишет
их в `HttpResponse.Body` с `await FlushAsync()` после каждой порции.
Заголовки:

- `Content-Type: audio/mpeg`
- `Transfer-Encoding: chunked` (без `Content-Length`)
- `Cache-Control: no-cache`
- `X-Accel-Buffering: no`

Соединение остаётся открытым до отключения клиента (`RequestAborted`).
При разрыве соединения счётчик слушателей уменьшается, ресурсы освобождаются.

### Станции (`StationManager`)

- Сканирует папку `wwwroot/audio/<станция>/` при запуске.
- Каждая страна хранит свой плейлист и общий индекс текущего трека.
- Индекс продвигается таймером — все клиенты станции слышат один и тот же трек.
- Счётчик слушателей потокобезопасен (`Interlocked.Increment/Decrement`,
  `Volatile.Read`).

### Веб-плеер

- `<audio controls>` подключается к `/stream/{станция}`.
- Выпадающий список позволяет переключать станции.
- Каждые 5 секунд обновляется информация о станции через `fetch('/stations')`.

## Проверено в работе

- `dotnet build` — 0 ошибок, 0 предупреждений.
- `/stations` возвращает JSON со всеми станциями.
- `/stream/{станция}` отдаёт `audio/mpeg` с `Transfer-Encoding: chunked` и без `Content-Length`.
- Два клиента на одной станции → счётчик = 2; после отключения → 0.
- Запрос к несуществующей станции → 404.
- Веб-страница плеера загружается с `<audio>`, `player.js`, `style.css`.
